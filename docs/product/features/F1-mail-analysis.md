# F1. 메일 분류 및 Vector DB 저장

> 상태: 초안 | 담당: C | 최종 수정: 2026-10-16
> 설계안: 화면·구조 설계안 v0.2 — 5쪽(분석·저장 과정), 6쪽(AI 분류 받은편지함)
> 화면 정의서: `docs/design/screens/` S03 (목업: `docs/design/screens/mockups/png/`)

## 1. 목적

메일이 들어올 때마다 AI가 읽고, 나중에 분류·검색·보고·제안에 쓸 수 있도록 **메타데이터 + 벡터** 두 가지 형태로 저장한다. F2(답장 초안), F3(검색), F4(주간 보고), F5(AI 스캔)가 모두 이 데이터를 쓴다.

사용자 입장에서는 메일을 열지 않아도 무엇에 관한 메일인지, 내가 할 일이 있는지 받은편지함에서 바로 알 수 있다.

## 2. 사용자 시나리오

1. 박지훈 과장(영업기획팀)이 "3분기 예산 집행 현황 자료 요청드립니다" 메일을 보낸다.
2. 몇 초 안에 받은편지함 목록에 메일이 나타나고, 다음이 함께 보인다.
   - 한 줄 요약: "◆ 부서별 집행 현황 엑셀을 금요일까지 요청"
   - 태그: `업무 요청` `회신 필요` `마감 10/16`
3. 메일을 열면 상단에 **AI 요약 박스**가 보인다: 요약 1~2줄 + "내가 할 일: 집행 현황 자료 송부 / 마감 10/16(금)"
4. 분류가 틀렸으면 "분류: 업무 요청 ▾"를 눌러 바꾼다. 이후 같은 발신자의 비슷한 메일은 바뀐 분류로 들어온다.

## 3. 처리 과정 (서버 파이프라인)

| 단계 | 하는 일 |
| --- | --- |
| 1. 수신 감지 | Gmail 신규·변경 메일 감지(데모: 폴링), 사용 시작 이후 메일만 처리 |
| 2. 전처리 | HTML → 텍스트, 인용문·서명 제거, 첨부 텍스트 추출(범위는 확인 포인트), 스레드 단위로 묶기 |
| 3. AI 분석 (LLM) | 카테고리 분류, 1~2줄 요약, 요청사항·마감 추출, 일정·인물·프로젝트 추출, 회신 필요 여부 판단 |
| 4. 메타데이터 구성 | 메일 기본 정보 + AI 분석 결과 결합, 정해진 형식(JSON 스키마)인지 검증 |
| 5. 임베딩·저장 | 본문을 단락 단위 청크로 나눠 임베딩, 요약도 따로 임베딩, 메타데이터 DB와 Vector DB에 저장 |

- 3단계 결과는 같은 시점에 **F5(AI 스캔)** 로 전달되어 일정 등록 제안 등에 쓰인다.
- 두 저장소는 `mail_id`로 연결한다. 벡터에도 기간·카테고리를 함께 저장해 필터와 같이 검색한다.

## 4. 메타데이터 항목

| 필드 | 예시 | 출처 |
| --- | --- | --- |
| `mail_id` / `thread_id` | msg_18f3a… / th_0921… | 메일 정보 |
| `from` | 박지훈 과장 (영업기획팀) | 메일 정보 |
| `to` / `cc` | 홍길동(수신), 이수진 팀장(참조) | 메일 정보 |
| `received_at` | 2026-10-14 09:12 | 메일 정보 |
| `category` | 업무 요청 | AI |
| `summary` | 3분기 부서별 예산 집행 현황 엑셀 자료를 금요일까지 요청 | AI |
| `action_items` | 집행 현황 자료 송부, 마감 2026-10-16(금) | AI |
| `needs_reply` | 예 | AI |
| `priority` | 높음 (팀장 참조, 마감 2일 이내) | AI |
| `entities` | 프로젝트: 3분기 결산 / 조직: 영업기획팀 | AI |
| `events` | 없음 | AI |
| `attachments` | 없음 | 메일 정보 |
| `user_label` | (사용자가 카테고리를 바꾸면 기록) | 사용자 |
| `archived` | 보관 여부, 예이면 삭제 전까지 유지 | 사용자 |

정확한 컬럼 타입은 `docs/architecture/data-model.md`에서 관리한다.

## 5. 카테고리 (고정 7종)

| 카테고리 | 기준 | 태그 색 |
| --- | --- | --- |
| 업무 요청 | 나에게 자료·작업·검토를 요청 | 파랑 |
| 회의·일정 | 회의 안내, 일정 조율 | 초록 |
| 결재·승인 | 전자결재 알림, 승인 요청 | 주황 |
| 보고·공유 | 보고서·자료 공유, 회신 불필요 | 갈색 |
| 공지 | 사내 공지, 교육 안내 | 회색 |
| 외부·고객 | 회사 밖(거래처·회계법인 등)에서 온 업무 메일 | 빨강 |
| 뉴스레터·광고 | 구독 메일, 광고 | 연회색 |

## 6. 받은편지함 화면 반영 (F0 화면 위에 추가)

- **스마트 보기** (사이드바): 회신 필요 / 마감 임박 / 할 일 — 각각 건수 표시
- **AI 카테고리** (사이드바): 7종 + 건수, 누르면 해당 카테고리만 보기
- **메일 목록 한 줄**: 발신자, 제목, ◆ 한 줄 요약, 태그(카테고리 / 회신 필요 / 마감 날짜 / 일정 제안)
- **메일 상단 AI 요약 박스**: 요약 + 내가 할 일 + 마감
- **분류 수정**: "분류: ○○ ▾ 틀렸다면 눌러서 변경"
- 목록 정렬: 기본 '중요도순', 시간순 선택 가능

## 7. 분류 정확도 높이기

사용자가 카테고리 수정 → 수정 이력 저장(`user_label`) → 비슷한 메일 분류에 반영.

- 예: '주간 금융 브리프'를 뉴스레터에서 보고·공유로 옮기면, 같은 발신자의 다음 메일부터 보고·공유로 분류
- 데모 구현: 같은 발신자에 대한 사용자 수정 이력을 LLM 프롬프트에 예시로 넣는 방식(few-shot)으로 시작

## 8. 데이터·API

- 파이프라인: `apps/server/app/pipeline/` (ingest → preprocess → analyze → embed)
- 프롬프트: `apps/server/app/ai/prompts/analyze.md`
- `GET /mails?category=업무 요청` / `GET /mails?smart=needs_reply|due_soon|todo`
- `PATCH /mails/{mail_id}/category` — 사용자 분류 수정
- 앱 실시간 반영: 분석 완료 시 WebSocket `mail.analyzed` 이벤트

## 9. 수용 기준

- [ ] 새 메일 도착 후 30초 안에 받은편지함에 요약·태그와 함께 나타난다 (데모 기준)
- [ ] fixture 메일 20건에 대해 카테고리 정답률 85% 이상 (`tests/evals/`)
- [ ] 마감이 있는 메일은 `action_items`에 날짜가 YYYY-MM-DD로 들어간다 ("이번 주 금요일" → 실제 날짜)
- [ ] LLM 응답이 스키마에 맞지 않으면 1회 재시도, 실패 시 '분류 실패'로 저장하고 원문은 그대로 보인다
- [ ] 스마트 보기 건수와 실제 목록 건수가 일치한다
- [ ] 분류를 수정하면 즉시 반영되고 `user_label`에 기록된다
- [ ] 메타데이터와 벡터가 같은 `mail_id`로 저장된다

## 10. 이번 범위 아님

- 사용자 정의 카테고리 추가
- 첨부파일(엑셀·PDF) 내용 분석 — 확인 포인트 결정 후
- 과거 메일 일괄 분석

## 11. 결정 사항 / 남은 확인 포인트

**결정 사항**

- 고정 카테고리 7종으로 시작, 사용자 수정을 학습
- 과거 메일 없이 사용 시작 이후 메일만 분석
- 보관 처리한 메일은 메타데이터·벡터 모두 삭제 전까지 유지

**남은 확인 포인트**

- 첨부파일 내용까지 분석·검색 대상으로 넣을지
- 사용자 프로필(담당 업무)로 중요도를 판단할지 (F2 연동)
