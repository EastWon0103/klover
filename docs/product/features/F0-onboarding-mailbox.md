# F0. 첫 실행 설정과 기본 메일함

> 상태: 초안 | 담당: A | 최종 수정: 2026-10-16
> 설계안: 화면·구조 설계안 v0.2 — 4쪽(첫 실행), 6쪽(받은편지함 기본 기능)
> 화면 정의서: `docs/design/screens/` S01 · S02 · S03 · S05 · S10 (목업: `docs/design/screens/mockups/png/`)

## 1. 목적

Klover는 Gmail을 **대체하는** 메일 앱이다. 사용자는 처음 실행할 때 5단계 설정을 거친 뒤, 과거 메일 없이 빈 받은편지함에서 시작한다. 이후 작성·보내기·보관·삭제·스팸 등 기본 메일 기능을 모두 Klover 안에서 쓴다.

AI 기능(F1~F5)은 이 기본 메일함 위에서 동작하므로, F0는 모든 기능의 바닥이다.

## 2. 사용자 시나리오

### 2-1. 첫 실행 (5단계 마법사)

1. **Gmail 계정 연결** — Google 로그인(OAuth)으로 Gmail 권한을 받는다. 연결된 계정 이메일을 표시한다.
2. **프로필 입력** — 이름, 직급, 소속, 담당 업무를 입력한다. (F2 프로필과 같은 데이터)
3. **문체 학습 동의** — "이 앱에서 보낸 메일의 표현과 문장 습관을 분석해 답장 초안에 반영합니다. 설정에서 언제든 끄고 학습 기록을 삭제할 수 있습니다." 안내 후 동의를 받는다.
4. **알림과 시작 프로그램**
   - Windows를 켜면 Klover 자동 실행 (기본 켬)
   - 창을 닫아도 트레이에서 계속 실행 (기본 켬, 완전 종료는 트레이 아이콘 → '종료')
   - AI 제안을 즉시 알림으로 받기 (기본 켬) + 유형 선택: 일정 등록 / 할 일 / 회신 필요 / 결재·승인 / 중요 발신자
   - 일정을 등록할 캘린더: Google Calendar 연결 상태 표시
   - 안내 문구: "앱이 꺼져 있던 동안 생긴 제안은 다음 실행 때 모아서 보여드립니다."
5. **완료** — 받은편지함으로 이동한다.

### 2-2. 빈 받은편지함

- 가운데에 "받은편지함이 비어 있습니다 / 지금부터 도착하는 메일을 AI가 분석합니다. 이전 메일은 가져오지 않습니다." 안내와 [새 메일 쓰기] 버튼
- 하단에 **기능 준비 상태** 표시

| 기능 | 상태 문구 |
| --- | --- |
| AI 분류·AI 스캔 알림 | 바로 사용 |
| 답장 초안 | 바로 사용 (문체 설정 기준) |
| 자연어 검색 | 메일이 쌓이는 대로 |
| 주간 보고 | 사용 1주 후부터 |
| 문체 학습 | 보낸 메일이 쌓이는 대로 |

### 2-3. 기본 메일 기능

- 화면 구조: 3단 — 왼쪽 사이드바 / 가운데 메일 목록 / 오른쪽 메일 읽기
- 상단: [새 메일] 버튼, 자연어 검색창(F3로 연결), 계정 이메일
- 사이드바 메일함: 받은편지함(안 읽은 수), 보낸편지함, 임시보관함, 보관함, 스팸·휴지통
- 사이드바 스마트 보기·AI 카테고리는 F1, '도구'(주간 보고, 설정)는 F4·F2에서 정의
- 메일 읽기 영역 버튼: [답장 초안 만들기] (F2), [답장], [보관], [삭제], [할 일 추가] (F5)
- 메일 작성: 받는 사람, 참조, 제목, 본문, 첨부, [임시 저장] [보내기]

## 3. 동작 규칙

- 과거 메일은 가져오지 않는다. **Klover 사용 시작 시점 이후에 도착한 메일만** 동기화·분석한다.
- 메일 계정 접근(읽기·보내기·보관·삭제)은 **서버가 담당**한다. 앱은 서버 API만 호출한다.
- 사용자가 보관한 메일은 사용자가 삭제할 때까지 서버에 유지된다(메타데이터·벡터 포함).
- 트레이 상주: 창 닫기(X) = 트레이로 숨김. 트레이 메뉴: 열기 / 종료.
- 시작 프로그램 등록은 설정에서 켜고 끌 수 있다.
- 설정 마법사를 중간에 끄면, 다음 실행 때 마지막 단계부터 이어서 한다.

## 4. 데이터·API

- `POST /auth/google` — OAuth 코드 교환, 서버가 토큰 저장
- `GET /mails?box=inbox&cursor=` — 메일 목록
- `GET /mails/{mail_id}` — 메일 상세
- `POST /mails/send` — 메일 보내기 (보낸 메일은 F2 문체 학습 대상)
- `POST /mails/{mail_id}/archive` / `DELETE /mails/{mail_id}` / `POST /mails/{mail_id}/spam`
- `PUT /settings/notifications` — 알림·시작 프로그램 설정
- 메일 데이터 구조: `docs/architecture/data-model.md`

## 5. 수용 기준

- [ ] 첫 실행 시 5단계 마법사가 나오고, 완료하면 다시 나오지 않는다
- [ ] Gmail 로그인 후 연결된 계정 이메일이 표시된다
- [ ] 첫 실행 직후 받은편지함이 비어 있고, 안내 문구와 기능 준비 상태가 보인다
- [ ] 사용 시작 이후 도착한 메일만 받은편지함에 나타난다 (fixture 커넥터로도 확인 가능)
- [ ] 메일 작성 → 보내기가 되고 보낸편지함에 나타난다
- [ ] 보관·삭제·스팸 처리가 동작한다
- [ ] 창을 닫으면 트레이로 숨고, 트레이 '종료'로만 완전히 종료된다
- [ ] '시작 프로그램' 설정이 켜져 있으면 Windows 로그인 시 자동 실행된다

## 6. 이번 범위 아님

- 오프라인 열람용 로컬 캐시
- 사외 웹메일(IMAP)·사내 메일(Exchange) 연결 — 2·3단계
- 여러 메일 계정 동시 연결

## 7. 결정 사항 / 남은 확인 포인트

**결정 사항**

- Gmail을 대체하는 메일 앱 (작성·보내기·보관·삭제·스팸 포함)
- 과거 메일 없이 빈 상태로 시작
- 첫 실행 때 문체 학습 동의
- 시작 프로그램 등록, 트레이 상주, 즉시 알림이 기본값

**남은 확인 포인트**

- Gmail에 이미 있는 메일이 앱에서 보이지 않는다는 점을 사용자에게 어떻게 안내할지
- 앱에서 보관·삭제하면 Gmail 쪽에도 똑같이 반영할지
- 기존 Gmail 라벨을 함께 보여 줄지
- 보관하지 않은 메일을 서버에 얼마나 보관할지
