# F5. AI 스캔 (수신 즉시 알림과 제안)

> 상태: 초안 | 담당: C | 최종 수정: 2026-10-16
> 설계안: 화면·구조 설계안 v0.2 — 12쪽(처리 과정), 13쪽(알림과 일정 등록 제안)
> 화면 정의서: `docs/design/screens/` S04 · S10 (목업: `docs/design/screens/mockups/png/`)

## 1. 목적

메일이 들어오는 순간 F1 분석 결과를 받아, 사용자가 해야 할 행동(일정 등록, 할 일, 회신 등)을 찾아 제안한다.

**원칙: 제안만 하고 실행은 사용자가.** 캘린더 등록이나 답장 발송을 자동으로 하지 않는다. AI는 내용을 채운 제안을 만들고, 사용자가 승인·수정·무시를 고른다.

## 2. 사용자 시나리오

1. 이수진 팀장이 "[안내] 3분기 결산 리뷰 회의" 메일을 보낸다 (일시: 10월 16일(금) 오후 2시~3시 30분, 장소: 본사 7층 대회의실).
2. 앱 창이 닫혀 있어도 **Windows 알림**이 뜬다.
   - "Klover · 일정 등록 제안 / 이수진 팀장: 3분기 결산 리뷰 회의 / 10/16(금) 14:00, 본사 7층 대회의실 / '팀 주간회의'와 시간이 겹칩니다"
   - 버튼: [캘린더에 추가] [메일 열기]
3. 메일을 열면 오른쪽에 **◆ AI 제안 N건** 카드가 정리되어 있다.
   - **일정 등록**: 제목·일시·장소·캘린더(업무 (Google) ▾)를 AI가 채움, 등록 전 수정 가능. 겹침 경고("같은 시간에 '팀 주간회의'(14:00~15:00)가 있습니다"). [캘린더에 추가] [무시]
   - **할 일**: "결산 자료 공유 폴더 업로드 / 마감 10/15(목)" [앱 할 일에 추가]
   - **회신**: "겹치는 일정이 있어 참석 여부 회신이 필요할 수 있습니다" [회신 초안 만들기]
4. 메일 본문에서 제안의 **근거 문장이 강조**(하이라이트)된다.

## 3. 처리 과정

```
새 메일 수신 → F1 분석(요청·마감·일정 추출) → 행동 감지(유형 판별) → 제안 만들기(제목·일시·장소 채움, 겹치는 일정 확인)
  → 앱 실행 중? ─ 예 → 즉시 Windows 알림
               └ 아니오 → 놓친 제안 보관 → 다음 실행 때 모아서 표시
  → 사용자 선택: 승인 / 수정 후 승인 / 무시
      승인 → 실행 (Google Calendar 등록, 앱 할 일 추가, 답장 초안 열기)
      무시 → 피드백 기록 (무시가 반복되는 유형은 감지 기준 조정)
```

## 4. 감지 대상

| 감지 대상 | 메일 속 예시 | AI 제안 | 승인하면 |
| --- | --- | --- | --- |
| 회의·일정 | "10/16(금) 14시, 본사 7층 대회의실에서 진행합니다" | 캘린더 등록 (겹치는 일정 경고) | Google Calendar에 등록 |
| 마감 있는 요청 | "이번 주 금요일까지 엑셀로 공유 부탁드립니다" | 할 일 추가, 마감 전날 리마인더 | 앱 안 할 일 목록에 추가 |
| 회신 요청 | "가능한 날짜를 회신 부탁드립니다" | 답장 초안 바로 만들기 | 답장 초안 창 열기 (F2) |
| 결재·승인 | 전자결재 시스템 알림 메일 | 결재 바로가기, 대기 건수 표시 | 결재 메일 열기 |
| 중요 발신자·긴급 | 팀장, 주요 거래처, 제목에 '긴급' | 요약과 함께 우선 표시 | 받은편지함 상단에 고정 |

- 중요 발신자: 데모에서는 프로필의 보고 대상(팀장) + 사용자가 지정한 발신자 목록

## 5. 알림 규칙

- 앱이 켜져 있으면 모든 제안을 **즉시 Windows 토스트 알림**으로 보낸다.
- 앱은 Windows 시작 시 자동 실행되고, 창을 닫아도 트레이에서 계속 실행된다 (F0).
- 앱이 꺼져 있던 동안의 제안은 **다음 실행 때 모아서** 보여 준다.
- 알림 유형별 켜기/끄기: 설정 > 알림·시작 프로그램 (F0 4단계와 같은 설정)
- 할 일은 앱 안에서 관리 (사이드바 스마트 보기 '할 일')

## 6. 데이터·API

- 서버: `pipeline/scan.py` (F1 analyze 결과를 입력으로 받음), `services/calendar.py`
- 제안 데이터: `{ suggestion_id, mail_id, type, payload, evidence_spans, status: pending|approved|dismissed, created_at }`
- 실시간: WebSocket `suggestion.created` → 앱 main 프로세스가 토스트 알림 표시
- `GET /suggestions?status=pending` — 놓친 제안 포함
- `POST /suggestions/{id}/approve` 입력: `{ payload? }` (수정 후 승인)
- `POST /suggestions/{id}/dismiss`
- `GET /todos` / `POST /todos` / `PATCH /todos/{id}`
- Google Calendar: 일정 등록, 겹치는 일정 조회(freebusy)

## 7. 수용 기준

- [ ] 일정이 담긴 fixture 메일 도착 후 30초 안에 Windows 알림이 뜬다
- [ ] 알림의 [캘린더에 추가]로 Google Calendar에 일정이 등록된다
- [ ] 같은 시간대에 기존 일정이 있으면 겹침 경고가 보인다
- [ ] 메일 화면의 제안 카드에서 제목·일시·장소를 고친 뒤 등록할 수 있다
- [ ] 어떤 제안도 사용자 승인 없이 실행되지 않는다
- [ ] 앱이 꺼져 있던 동안 생긴 제안이 다음 실행 때 모아서 보인다
- [ ] 무시한 제안은 다시 알리지 않고, 무시 기록이 저장된다
- [ ] 제안의 근거 문장이 본문에서 강조된다
- [ ] 설정에서 끈 유형은 알림이 오지 않는다

## 8. 이번 범위 아님

- 사내 그룹웨어 캘린더 (3단계에서 검토)
- 무시 기록을 이용한 감지 기준 자동 조정 (데모에서는 기록만)

## 9. 결정 사항 / 남은 확인 포인트

**결정 사항**

- 앱 실행 중 모든 AI 제안을 즉시 알림
- 시작 프로그램 등록, 트레이 상주
- 캘린더는 Google Calendar, 할 일은 앱 안에서 관리

**남은 확인 포인트**

- 제안 유형별로 알림을 끌 수 있게 할지 (위 5장은 '끌 수 있음'으로 가정)
- 알림에서 바로 캘린더 등록까지 허용할지, 앱을 열어 확인하게 할지
- AI 스캔에도 프로필(담당 업무)을 반영해 중요도를 조정할지
